## 2026-11-25 · DB 설계와 db.md

| 항목 | 작성 |

| 목표 | 스노우볼과 오너먼트를 저장할 테이블을 설계하고, 메시지는 주인만 읽도록 권한을 잡는다. |
| 프롬프트 | "Supabase 테이블 설계하고 db.md 작성해 줘. 기존 wanted_practice 프로젝트를 그대로 쓰고 스키마 이름만 안 겹치게 하면 되지 않을까?" 에이전트의 질문에 답: 메시지는 주인만 읽기, 링크 이름은 사용자가 직접 정할 수 있게. 첫 설계를 본 뒤 추가 지시: "주인이 무작위 32자 링크를 항상 알고 있어야 하는 건 불편하다. 주소 + 비밀번호 방식으로 바꿔 줘." 이어서: "주소는 서비스에서 닉네임이라고 부르고, 닉네임과 비밀번호를 입력하면 본인의 홈으로 가게 하자." |
| 결과 | `snowglobe` 스키마에 테이블 3개(globes, ornaments, owner_sessions)와 함수 9개를 만드는 SQL, 설계를 설명한 `db.md`. 테이블은 RLS로 직접 접근을 막고 함수로만 읽고 쓰게 함. 주인은 직접 정한 닉네임 + 비밀번호로 본인의 홈을 열고, 열면 받는 토큰으로 메시지를 읽음. 닉네임은 한글도 가능하고 공유 링크로도 쓰임. 비밀번호 5번 틀리면 10분 잠금. |
| 검증 | SQL을 임시 Postgres(PGlite)에 실행해 59가지 경우를 시험, 모두 통과(직접 접근 차단, 입력 검사, 비밀번호로 열기, 틀린·만료된·남의 토큰 거부, 잠금, 몰아서 달기 제한). 실제 Supabase에는 아직 적용하지 않음. `npm run lint`, `npm run build` 통과. |
| 수정 | 처음에는 에이전트가 "무작위 주인 열쇠가 든 비밀 링크" 방식으로 설계했으나, 주인이 긴 링크를 보관해야 해서 불편하다고 판단해 닉네임 + 비밀번호 방식으로 다시 설계하게 함. 닉네임에 한글을 허용한 것은 에이전트 제안. 정식 로그인도 검토했지만 설정 시간과 인증 메일 제한 때문에 선택하지 않음. 글자 수·개수 제한과 잠금 기준(5번, 10분)은 에이전트가 정한 값. (본인 확인 필요) |
