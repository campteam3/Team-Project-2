## 2026-11-25 · Blender로 3D 스노우볼 모델 만들기

| 항목 | 작성 |
| --- | --- |
| 목표 | 서비스에 쓸 3D 스노우볼(트리, 눈사람, 선물, 받침대)을 Blender로 만들고, 메시지 오너먼트를 달 수 있는 구조로 웹용 파일을 내보낸다. |
| 프롬프트 | "이런 느낌의 클레이 3d 로 만들고싶어. 가운데에는 크게 트리가 들어가야하고 주변에는 선물상자랑 눈사람을 넣어줘." 이후 레퍼런스 이미지를 주며 부분별로 지시: 트리를 두툼한 도자기 느낌으로, 오너먼트는 구체가 아니라 고리가 트리에 닿게, 선물은 반듯한 상자 6개로, 눈은 소복하게, 받침대는 빨간색에 금색 테두리와 호랑가시나무 · 눈송이 양각으로. 마지막 지시: "메세지 달 때 오너먼트 모양이나 색을 정할수있게 하는거라서, 오너먼트나 하트 별 모두 채워질 자리가 되어야해. 기본으로 적은 수만 매달려 있는게 나을것 같아" |
| 결과 | Blender 원본(`design/blender/snowglobe.blend`)과 웹용 파일: 스노우볼 본체(`public/models/snowglobe.glb`, 4.2MB, 삼각형 약 23만 개), 오너먼트 원형 3종(`ornaments.glb`: 볼 · 별 · 하트), 오너먼트 자리 39곳과 기본 장식 7개 데이터(`lib/snowglobe-slots.json`). |
| 검증 | 단계마다 Blender에서 렌더하거나 미리보기를 찍어 레퍼런스와 비교했다. 오너먼트와 쿠키가 트리에 파묻히지 않는지는 표면까지의 거리를 계산해 전부 겹치지 않음을 확인했다. 웹용 파일은 아래 항목의 화면 작업에서 실제로 띄워 확인했다. |
| 수정 | 트리는 레퍼런스와 다르다는 지적을 받아 여러 번 다시 만들었다(바늘잎 → 물결 주름 → 층을 쌓는 방식). 층 개수, 갈래 모양, 비율은 본인이 렌더를 보고 하나씩 지시했다. 장식이 파묻힌다는 지적으로 갈래 끝에 고리로 거는 방식으로 바꿨다. 선물은 "부자연스럽게 둥글다"는 지적으로 반듯한 상자로 다시 만들었다. 받침대는 나뭇결이 올드하다는 판단으로 빨간색으로 바꿨다. 작업 중 Blender가 무거운 렌더로 한 번 멈춰서, 이후에는 가벼운 미리보기로 확인했다. |
| 배운 점 | 생각보다 레퍼런스대로 나오지 않아서, 꽤 구체적으로 지시하는 것이 필요했다. |

## 2026-11-25 · 스노우볼 보기 화면에 모델과 메시지 오너먼트 적용

| 항목 | 작성 |
| --- | --- |
| 목표 | 실험용 3D 화면(`/globe/demo`)을 Blender로 만든 스노우볼로 바꾸고, 메시지 오너먼트가 모양과 색대로 트리 자리에 달리게 한다. |
| 프롬프트 | "웹화면작업 진행해" (앞서 정한 방향: 볼 자리와 쿠키 자리를 모두 메시지 자리로 쓰고, 기본으로는 적은 수만 달아 둔다) |
| 결과 | `components/SnowGlobeScene.tsx`를 새로 작성(모델 불러오기, 유리 재질, 주변 빛, 화면 비율에 맞춘 카메라 거리, 흔들면 눈 날리기). `lib/snowglobe.ts`에 자리 데이터와 배정 규칙 추가. 샘플 메시지 5개가 볼 · 별 · 하트로 달리고, 누르면 메시지가 뜬다. |
| 검증 | `npm run lint`, `npm run build` 통과. 개발 서버를 띄우고 브라우저 자동화(Playwright)로 휴대폰 크기와 PC 크기 화면을 캡처해 확인: 스노우볼 전체 표시, 흔들기 버튼으로 눈 날림, 오너먼트 클릭 시 메시지 2건 표시, 드래그로 회전. 콘솔 오류 없음. 본인이 브라우저에서 직접 열어 확인했다. 실제 휴대폰에서의 속도와 흔들기 센서는 확인하지 못했다. |
| 수정 | 첫 화면에서 스노우볼이 작고 받침대가 잘려서 카메라 거리 계산을 두 번 고쳤다. 유리가 뿌연 원판처럼 보여 가장자리가 빛나는 재질로 바꿨다. 트리 색이 허옇게 떠서 색과 조명을 조정했다. 유리 · 카메라 · 자리 배정 방식은 에이전트 판단. 팀장이 만든 `lib/sample-data.ts`는 고치지 않고, 모양 값은 화면 확인용으로 임시로 붙였다. |
| 배운 점 | 아직 디테일한 질감 작업을 하지 않아서 추후 진행할 예정이다. |
