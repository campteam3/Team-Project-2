| 검증 | 에이전트: 미리보기로 데스크톱 · 모바일에서 10~13 을 눌러 가며 스크린샷 확인, DB 키 없는 실제 주소의 오류 화면 확인. lint · build 통과, Impeccable 검사 0건. 실제 DB 저장은 키가 없어 확인 못 함. 사람 확인: 김미영이 개발 서버의 `/globe/demo?preview=friend`에서 10~13을 확인함 |
| 수정 | 오너먼트 위치가 전체 개수에 따라 바뀌어 하나가 달릴 때 전부 움직이던 문제 → 달린 순서만으로 위치가 정해지게 바꿈. 새 오너먼트가 트리 뒤쪽에 달려 안 보이던 문제 → 11~13 동안 그 오너먼트가 정면에 오도록 스노우볼을 돌림. 12 에서 작아진 스노우볼의 명판 글자가 넘치던 문제 → 그 단계에서는 숨김. 사람 수정: 다음 작업으로 PRD 최우선 흐름인 친구 흐름(10~13)을 먼저 하기로 정하고, Figma 시안 없이 바로 코드로 진행하도록 결정함. 제안된 4가지를 승인함(모양 대신 색 6개, 질문 문구 없이 안내만, "주인이세요?"는 도크 아래 링크, `?preview=friend` 미리보기) |
| 배운 점 | 시간이 부족할 때는 시안을 거치지 않고, 정해 둔 디자인 규칙으로 바로 코드를 만들고 화면을 보며 고치는 편이 빠르다. 대신 오너먼트가 뒤에 숨는 것처럼 3D에서만 보이는 문제는 직접 화면을 돌려 봐야 찾을 수 있다. |

## 2026-11-25 · 친구 흐름 두 번째 버전 (오너먼트에 집중, ?flow=2)

| 항목 | 작성 |
| --- | --- |
| 목표 | 첫 번째 친구 흐름은 그대로 두고, 오너먼트에 집중하는 두 번째 버전을 만들어 A/B 로 비교할 수 있게 하기 |
| 프롬프트 | "마음 달기를 누르면 트리 없이 오너먼트만 보이고, 고르면 작아지며 위로 가고 입력 창이 뜨고, 다음을 누르면 아래서 스노우볼이 올라와 오너먼트가 천천히 작아지며 트리에 달리는 장면" → 파일 목록 · 결정 3가지 제안 → "제안대로 진행해줘" |
| 결과 | 새 파일 2개(FriendFlowFocus, OrnamentShowcase). 11′ 스노우볼이 아래로 내려가고 커다란 3D 오너먼트 6개(누르거나 색 버튼으로 고름) → 12′ 고른 오너먼트가 작아지며 위로, 메시지 카드 → 13′ "달기"에 저장 후 스노우볼이 올라오고 오너먼트가 포물선을 그리며 작아져 트리 제자리에 달림 → 완료. 주소에 `?flow=2` 를 붙이면 두 번째 버전, 없으면 첫 번째 버전 |
| 검증 | 에이전트: `/globe/demo?preview=friend&flow=2` 로 데스크톱 · 모바일에서 고르기 · 쓰기 · 달리는 도중 · 완료를 캡처해 확인. lint · build 통과, Impeccable 검사 0건. 사람 확인: 김미영이 `?flow=2` 미리보기에서 고르기 · 쓰기 · 달리는 장면을 보고, 12′의 오너먼트 크기와 위치를 두 번 조정하도록 요청함(카드에 딱 붙어 이상함 → 카드 뒤로 30% 겹치게) |
| 수정 | 모바일 12′ 에서 올라간 오너먼트가 부제와 겹쳐 위치를 내림. 고른 오너먼트의 빛무리가 남색 배경과 섞여 회색으로 보여 금빛 고리로 바꾸고, 고리가 납작해 보이지 않게 회전을 멈춤. 사람 수정: 12′ 에서 오너먼트를 더 크게, 입력창 가까이 내려 달라고 요청 → 크기를 약 1.8배로 키우고 카드 바로 위(모바일은 카드 뒤로 살짝 겹치게)로 내림 → 카드에 딱 붙어 이상하다는 피드백으로, 지름의 30%가 카드 뒤로 겹치도록 카드 위치를 화면 아래 기준(px)으로 계산 |
| 배운 점 | 같은 기능도 "트리 위에서 고르기"와 "오너먼트에 집중하기"처럼 화면 흐름을 다르게 만들 수 있다. 두 버전을 함께 두면 A/B로 어느 쪽이 더 빨리, 더 많이 끝까지 다는지 비교할 수 있다. 3D 위 UI는 딱 붙이기보다 살짝 겹쳐야 한 장면처럼 보인다. |
